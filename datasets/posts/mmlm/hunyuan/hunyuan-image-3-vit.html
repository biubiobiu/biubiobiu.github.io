ViT 通路深度剖析：NaFlex 预处理 → SigLIP2 → 2 层 MLP

HunyuanImage-3.0-Instruct 深挖专题 ① · 贯穿示例：1024×1024 参考图 · 所有数值来自官方 checkpoint config（vit / vit_processor / vit_aligner）与 siglip2.py / image_processor.py 代码 · ← 返回总览
一句话总结：ViT 通路把任意尺寸的参考图自动缩放到 ≈1024 个 16×16 patch（NaFlex，不裁剪、近似保比例、小图放大大图缩小），过一个 27 层、400M 参数的 SigLIP2-so400m 双向 Transformer（d=1152），再经 Linear 1152→4096 → GELU → Linear 4096→4096 对齐到主干维度——输出恒为 (1024, 4096) 的「视觉词」，scatter 进统一序列中参考图 joint 段 <joint_img_sep> 之后的 1024 个 <img> 坑位。全程无时间步参与、权重冻结 ❄。

一、数据流总览图（示例：1024×1024 参考图）

ViT 通路完整数据流。NaFlex 让任意比例的图都被「顶格」编码为 ≈1024 个 patch；SigLIP2 27 层内形状恒定 (1024, 1152)；aligner 只做维度翻译不做 token 交互。

二、疑点解析（阅读中随时追加）

疑点 ①：SigLIP2 输入 1024 个 token、输出还是 1024 个 token——27 层 Transformer 不是应该"逐个预测下一个 token"吗？这是预测了未来的 1024 个 token 吗？

不是预测。Transformer 有两种截然不同的用法，"逐个预测下一个 token"只属于其中的解码器用法；SigLIP2 是编码器，它不生成任何新 token：

解码器（GPT / 本模型 80B 主干的 gen_text 模式）编码器（BERT / ViT / SigLIP2）
注意力因果 mask，只能看左边双向，每个 token 看所有 token
任务逐个预测下一个 token改写每个 token 自己的表示
输出头lm_head → 词表 softmax → 采样出离散 token没有词表头，输出就是连续向量
输入输出关系错一位（输入第 1..n 个，预测第 2..n+1 个）一一对应（第 i 个输出对应第 i 个输入）
前向次数自回归循环，每生成一个 token 前向一次一次前向出全部结果
  • 所以 (1024, 1152) → 27 层 → (1024, 1152) 的正确理解：始终是同一批 1024 个 token，没有新增、没有位移，第 i 个输出向量严格对应第 i 个输入 patch（空间位置不变，仍是行主序 32×32 网格）。
  • 27 层做的是「精炼」而非「生成」：进门时第 i 个向量只知道自己那 16×16 像素块（纯局部信息）；每过一层双向注意力就吸收一次全图上下文；出门时同一位置的向量已变成"我这块是猫耳朵，属于画面中央那只橘猫"式的全局语义描述——位置没变，内涵变了。
  • 它没有预测能力的三个证据：无因果 mask（能看见"未来"，预测即作弊）、无词表分类头（输出是连续向量不是离散 token）、无自回归循环。
  • 类比：编码器像翻译官——1024 句"像素方言"逐句翻成"语义普通话"，句数不变；解码器像说书人——一句接一句往下编。SigLIP2 的角色是给主干「备料」，真正逐 token 预测的只有 80B 主干的文本出口。
  • SigLIP2 原始训练目标是图文对比学习（sigmoid contrastive），学的就是「输出好的语义表示」，与语言建模无关；在本模型中权重冻结，纯当特征提取器。
  • 伏笔：80B 主干处理图像 token 时（gen_image 模式）其实也切换成了「编码器式」用法——图像段内部双向注意力、出口不走词表头而走 UNetUp 出速度场。剖析主干时再展开。
疑点 ②：GPT 里选词的 softmax 只在最后一层之后——那中间层输出的是 [batch, 1, hidden] 吗？

分阶段看，两种形状都存在：

阶段每层进出形状说明
decode（逐 token 生成，配 KV cache）[B, 1, hidden]只喂刚生成的 1 个 token；它的 Q 新算，K/V = 自己的新 K/V + 从 KV cache 读出的全部历史 → 形状是 1 却看得到全部上文
prefill（首次处理整段 prompt）[B, L, hidden]所有位置并行；lm_head 出 [B, L, vocab] 后只取最后一个位置的 logits 选词，其余位置的价值是把 KV cache 填满
训练[B, L, hidden]L 个位置的 logits 全都用：第 i 位拟合第 i+1 个真实 token，一次前向 = L 个预测任务（解码器训练效率高的根源）
  • 两个 softmax 别混淆：中间层没有「词表 softmax」，但每层注意力内部都有「注意力 softmax」——它作用在 (B, heads, L_q, L_kv) 的分数矩阵上，算的是注意力权重分配，与选词无关；选词的 softmax 全网只有 lm_head 之后一处，作用在 vocab 维上。
  • 中间层进出永远是 hidden 维连续向量、形状不变——第 i 个位置的向量逐层被精炼，这一点和编码器完全一样。解码器 vs 编码器的中间层数学形式几乎相同，真正的差别只有：mask 方向（因果 vs 双向）+ 最后一层之后干什么（接词表头预测 vs 直接当特征输出）。
  • 对应本模型的 decode 步：gen_text 每步 forward [B, 1, 4096]（标准 GPT 式）；gen_image 每步 forward [B, 1+4096, 4096]（timestep token + 画布 token 一起回炉）——「批量版 decode 步」，出口不走词表头而走 UNetUp。

三、细节与坑（值得记住的边角）

  • 序列坑位恒为 1024：tokenizer 按 max_num_patches 预留 1024 个 <img>，非方图时尾部 pad patch 的输出向量也会被 scatter 进序列（ViT 内部 mask 只挡「被注意」，不删行）。主干里这些 pad token 是可被看见的低信息 token。
  • 位置码容量 vs 实际长度：可学习位置码只有 16×16=256 个（num_patches=256），推理时总要插值放大到 ~32×32 用——「256 学、1024 用」是 naflex 的设计常态。
  • pooling head 白算：vision_use_head 未配置 → 默认 True，MAP 池化头每次前向都执行，但 _forward_vision_encoder 只取 last_hidden_state，pooler_output 直接丢弃。
  • joint_full 注意力：checkpoint 配置 cond_token_attn_type="joint_full"——参考图的 [VAE 4096 + sep + ViT 1024] 作为一个整体开双向注意力方块（比 "full" 更大范围：两路 token 互见）。
  • 2D RoPE 坐标：ViT 段在主干里按 spatial_shapes 铺 2D 网格坐标（与 VAE 段同一套居中对齐公式）；非方图时 1008 真实 + 16 pad 的 pad 部分坐标顺延成对角线（文本式），属无伤大雅的实现细节。
  • 本模块与 Qwen2.5-VL 视觉塔的对比：SigLIP2 无窗口注意力、无 2×2 token 合并、无 M-RoPE——是更「朴素」的 ViT；代价是 token 数固定 1024 不随图大小变化。
